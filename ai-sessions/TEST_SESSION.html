The session in one paragraph

The optimizer from the build sessions was run once on the 10-case held-out trap set, which was built outside the build sessions. It got 10/10 correct with a geomean cycles ratio of 0.730. This session explained the report, then looked at why three cases came back at 1.000. In all three the optimizer printed the input unchanged, because no existing pass matched. For each case we worked out a cheaper rewrite that is still legal. We then estimated how long each would take to build and what it would do to the overall number. We decided not to take the tempting shortcut of having the optimizer replay known answers, because that would overfit to the held-out set. Later in the session we built those rewrites as rules 9–11, each with a buggy twin. That brought the held-out ratio to 0.602 with 10/10 still correct, and the meta-eval to 44/44 bugs caught with 0 false alarms. The session also packaged the submission, followed the repo reorganisation, and fixed the tool paths it broke.

The three cases left untouched

In all three, every existing pass (DCE, CSE, GATHER composition, filter-first, sort removal, join swap) failed to match anything, so the guard in optimizer/main.py printed the input unchanged. Staying correct was right; the cost was a missed speedup.

Decisions made

  • No answer replay. Making the optimizer recognise held-out programs, or output stored legal rewrites, would score well while proving nothing about programs it hasn't seen.
  • Prefer general rules. Cases 03 and 06 are the same kind of problem: simplifying a filter that feeds IDX without breaking three-valued logic. One NULL-aware predicate pass covers both.
  • The evaluator speeds up testing but doesn't prove safety. Rules still have to be sound by construction, using the schema constraints and never the stats.
  • Package without .git. An early commit contains the one-pager PDF, so the full history ships as text in git-history/ instead.
  • Held-out set excluded from the package. This session's transcript does quote three of its cases, and SUBMISSION.md says so.
