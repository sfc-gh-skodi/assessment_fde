What we learned

  1. The big wins are generic. Filter first, build strings late, gather only the columns that reach OUT, delete dead code, use TOPK. These gave 4–8.5× on q0001, q0004 and q0007. The self-join idioms win most on large data (20–47×), and they are the riskiest.
  2. Correctness may use constraints, never stats. customers has no key, so assuming c_id is unique is a real bug, caught by the q0004 baseline.
  3. NULL semantics are the main trap. HJOIN drops NULL keys but GROUP keeps them, and NULLIFE turns '' into NULL.
  4. An operation may only run on a subset of the rows it originally ran on. Removing work can only remove errors, which is allowed.
  5. Weak data hides bugs. The example data passed two broken q0007 variants, and generated data missed a q0004 bug until literals from the programs were planted in it.
  6. Multiset comparison is too lenient when the program sorts, and an order rule fixes it. The output JSON has no types, so BOOL must never equal INT, and only text in minivm's own number format may be compared as a number.
  7. Test the tester. Zero defects proves nothing until seeded bugs are caught and honest-but-different optimizers pass.
  8. Measure the harness too. The platform binary is 4.6× faster than the wrapper, which leaves the 2-minute budget roomy.
